# ПОС — преподавательская оценка студентов

Консольное приложение для ведомости одного курса. Преподаватель задаёт критерии и их вес, выставляет оценки студентам и выгружает итоги в CSV. Например, если Маша получила 8 из 10 за лабораторную с весом 60, а экзамен с весом 40 ещё впереди, программа покажет 80% за оценённые работы и 48% за весь курс.

## Запуск

Нужен Go 1.27 или новее. Откройте терминал в корне проекта, рядом с `go.mod`, и выполните команду:

```sh
go run ./cmd/pos
```

| Пункт меню | Действие |
|---|---|
| 1, 2 | Добавить студента или критерий |
| 3, 4 | Выставить оценку или посмотреть оценки студента |
| 5, 6 | Посмотреть список студентов или рубрикатор |
| 7, 8 | Исправить или отменить существующую оценку |
| 9 | Рассчитать оба итога студента |
| 10 | Записать итоги всех студентов в `totals.csv` |
| 0 | Сохранить изменённую ведомость в `gradebook.json` и выйти |

Оба файла появляются в рабочей папке программы. При запуске приложение загружает ведомость из этой папки. Чтобы сохранить введённые оценки, завершите сеанс пунктом **0**.

## Демонстрация

Команды для macOS и Linux запускают готовый сценарий в отдельной временной папке. Выполните их из корня проекта:

```sh
demo_dir=$(mktemp -d)
go build -o "$demo_dir/pos" ./cmd/pos
(cd "$demo_dir" && ./pos) < examples/masha.stdin
cat "$demo_dir/totals.csv"
```

Сценарий регистрирует Машу и два критерия. Программа принимает 8 за лабораторную и отклоняет попытку поставить 12 из 10. После выставления 15 из 20 за экзамен оба итога равны 78%: лабораторная даёт `8 / 10 × 60 = 48`, экзамен — `15 / 20 × 40 = 30`. В CSV результат выглядит так:

```csv
student_id,name,current_percent,course_percent
masha,Маша,78.00,78.00
```

## Доменная модель (DDD)

| Термин | Тип в Go | Решение |
|---|---|---|
| Студент | `Student` | Сущность с постоянным ID. У двух студентов могут совпадать имена. |
| Критерий | `Criterion` | Объект-значение из названия, максимума и веса. Например, «Лабораторная, 10, 60». Рубрикатор хранит копию этого значения и находит его по названию. |
| Рубрикатор | `Rubric` | Корень агрегата критериев курса. Метод `AddCriterion` проверяет уникальность и непустое название, положительный максимум и вес. |
| Оценка | `Evaluation` | Запись с составным ключом «ID студента + название критерия». Исправление меняет балл той же записи. Отмена удаляет её. |
| Итог | `Totals` | Вычисляемое значение с двумя процентами. Доменный сервис `CalculateTotals` получает рубрикатор и актуальные оценки одного студента. |

Студенты и их оценки хранятся отдельно от рубрикатора. При выставлении оценки сценарий `Gradebook.SetScore` проверяет регистрацию студента. Затем рубрикатор проверяет наличие критерия и диапазон от нуля до максимума включительно. В хранилище попадает только проверенная оценка.

Для текущего результата знаменатель равен сумме весов оценённых работ. Для итога курса знаменатель равен сумме весов всех критериев. Выставленный ноль включает работу в оба расчёта. Если знаменатель равен нулю, консоль выводит пояснение, а CSV оставляет поле пустым. [Расчёт итогов](domain/total.go)

## Архитектура — Ports and Adapters

Основное направление зависимостей в коде — **адаптеры → приложение → домен**.

| Папка | Ответственность |
|---|---|
| [domain](domain) | Правила создания оценок, рубрикатор и расчёт процентов |
| [application](application) | Сценарии преподавателя и выходной порт `Repository` — интерфейс хранения студентов и оценок |
| [adapters/console](adapters/console) | Входной адаптер. Читает команды и передаёт их ведомости через методы `Gradebook` |
| [adapters/memory](adapters/memory) | Реализация порта `Repository` для текущего сеанса |
| [adapters/files](adapters/files) | Загрузка и сохранение JSON, экспорт рассчитанных процентов в CSV |
| [cmd/pos](cmd/pos) | Точка сборки приложения. DI-контейнер `dig` подставляет хранилище в памяти и рубрикатор в конструктор `Gradebook` |

## Паттерны

| Группа | Решение и место в коде | Какую задачу решает |
|---|---|---|
| Порождающие | **Фабрика оценки** — [Rubric.NewEvaluation](domain/rubric.go) | Создание оценки требует данных рубрикатора. Простая фабрика возвращает готовую оценку после тех же проверок, которые действуют при исправлении. Это вариант «Фабрика» из примеров задания. |
| Структурные | **Facade** — [Gradebook](application/gradebook.go) | Консоли достаточно вызвать `SetScore`. Поиск студента, создание оценки и запись выполняет ведомость. |
| Поведенческие | **Strategy** — [gradedOnly и allCriteria](domain/total.go) | Функция `weightedPercent` принимает правило включения критерия. Замена правила позволяет использовать одну формулу для двух итогов. |

## Проверки

В терминале из корня проекта выполните:

```sh
go test -count=1 ./...
go vet ./...
```

Тесты домена проверяют границы балла, неизвестный критерий и расчёт итогов при пропуске, нуле и полном наборе оценок. Тесты консоли проверяют исправление и отмену. Тесты файлового адаптера проверяют восстановление оценок из JSON, содержимое CSV и сохранность файла при конфликте изменений.
